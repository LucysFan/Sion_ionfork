# Высота 150 и кратные острова — как это работает теперь

## 1. Высота 150: seed ≠ реальная высота, но теперь авто-подстройка

**Раньше:** `minimum_seed_m: [0,0,150e-6]` на ловушке `90 мкм` (top 90/cent 110) или `199 мкм` (300/200) всё равно давал `90` или `199` — seed лишь начальная точка для `SionTrap.local`.

**Сейчас:** `Runner` умеет авто-подбирать геометрию, если вы явно просите высоту.

```json
"trap": {
  "kind": "sion_five_wire",
  "minimum_seed_m": [0,0,150e-6],
  "target_height_m": 150e-6,       // явно хотим 150
  "auto_tune_height": true,        // разрешить подбор
  "geometry": { "top_rf":[20000,90], "central_dc":[20000,110], ... }
}
```

При `target_height_m` или при `seed=150` + `auto_tune_height:true` и расхождении >7 мкм, `Runner` перебирает `top_rf 90..220` и `central 110..200` + `rf 24..120В` и выбирает ближайшую высоту с хорошей секулярной `0.40..0.85 МГц`.

**Что получается для 150 мкм:**

- Точный 150 мкм на `five_wire` даёт `f0≈0.35 МГц` и `weak_confinement` для 100 мкм шаттла — не проходит `min_frequency 0.4 МГц`.
- Ближайший с хорошим шаттлом: `top 140 cent 200 rf 80 20МГц → h 144.0 мкм, f0 0.41 МГц, sta n=0.75` (vs 136 мкм n=0.44). Это и выбирает авто-тюн — `144` вместо `150`, на 6 мкм ниже, но шаттл работает и с `K` и без, а точный 150 — нет.
- На дашборде в шапке Trap теперь видно оба: `высота 144 мкм (seed 150 мкм) · RF 20 МГц · границы -20…20 В`. Если видите `90 (seed 150)` — авто-тюн выключен.

> Для **точного** 150 мкм нужен кастомный GDS (сгенерируйте `five_wire` с масштабом или нарисуйте в KLayout). `five_wire` аналитический имеет дискретный набор высот с хорошей связностью.

**Конфиги:**

- `configs/shuttle_150um_auto.json` — авто 150 (факт 144) + 8 островов включая `K`/`K5` isolated 100%, 100 мкм/100 мкс.
- `configs/shuttle_90um_100um_krat.json` — 90 мкм, 100 мкм/100 мкс, 8 островов с `K`.
- `configs/shuttle_60um_krat.json` — пример произвольного `60 мкм/60 мкс` с авто `K`.

Запуск:

```bash
PYTHONPATH=. python -m shuttle_sim.pipeline --config configs/shuttle_150um_auto.json --out output/150auto
python get_shuttle.py --config configs/shuttle_150um_auto.json --out output/150auto --generations 30 --dashboard
```

## 2. Кратые острова (K) — непрерывный 5×20 как один путь, для любого расстояния

### Идея

`5×20 мкм / 5×20 мкс` — это **один непрерывный** путь с холдами между сегментами, а не 5 независимых оптимизаций. Наивный `100 мкм` требует `>±12 В` и `n~17`, а `20 мкм` укладывается в `±12 В` и `n~0.03` (на 199 мкм) или `±20 В` и `n~2.6` (на 90 мкм, stitched). Чтобы GA мог найти оба, вводим **изолированные острова**, которые внутри себя считают кратные.

### Как устроены K-острова

- **Стратегия `K`, `K5`, `K3`...** — `K` = `auto` (сегментов `round(D/20мкм)`), `K5` = 5 сегментов, `K3` =3 и т.д. `pop 12`, `baseline sta`, `isolated_until 100%` — **не мигрируют** с обычными `S/A/V/W/R/H`, но участвуют в общем `hall_of_fame` и статистике.
- **Для любого `D`:** `segments = max(2, min(10, round(D/20um)))` если `auto`. Примеры: `D=100→5`, `60→3`, `30→2`, `150→8`, `20→1` (вырождается в обычный).
- **Внутри острова:** `theta` тот же (`8` генов), но `Runner.commands_segmented(theta, segments)` строит **сшитый** `s(t)`: `0→1/segments` за `seg_T`, холд `2 мкс` на `1/segments`, `1/segments→2/segments` и т.д. `seg_T = (total_T - (K-1)*hold)/K` чтобы суммарно `≈ total_T`. Напряжения `v = voltage_spline(route) + stitched ΔV` (тот же `theta` применяется к каждому сегменту с его `envelope(s_grid)`). Затем **один** `Hardware.deliver` через фильтр — непрерывно, без сброса состояния между сегментами. Далее тот же `ROM + propagate` — `n_total` уже для всего сшитого пути, сравним с прямым.
- **Фитнес:** тот же `scalar_fitness` от `n_total`, `pos`, `well`, `lag`, `distortion`, `fmin`. Для `K` `n` обычно меньше (90 мкм 100 мкм: `A n=17.2` vs `K5 n=9.0`; 60 мкм: `A n=154` vs `K n=9.1`), поэтому в hall часто выигрывает `K`.
- **Авто-добавление:** если в `ga.islands` нет `K/M/C` и `D≥25 мкм` и `auto_add_krat != false`, `GAEngine` сам добавит `K (auto)` и `K5` как изолированные 100%. В `shuttle_90um_100um_100us.json` без явных `K` они появятся автоматически; в `*_krat.json` они уже явно прописаны и `auto_add_krat:false` чтобы не дублировать.

### Почему изолированные и не взаимодействуют

- `isolated_until = generations` → кольцо миграций их пропускает до конца, `migrant` не приходит/не уходит. Это сохраняет нишу: обычные острова ищут прямой путь, `K` — сшитый. В `hall` они соревнуются честно по `fitness`, лучший из всех попадает в `hall[0]` и в `sion_export.json`.
- На дашборде: вкладка **Migration** показывает тёмный фон = изоляция, кольцо без стрелок к `K`; вкладка **Islands** — `K` в таблице с `isolated 100%`; **Trap** — траектории `K` рисуются тем же `voltage_spline` но с холдами, видно ступеньки на `s(t)`.

### Для произвольного расстояния

Не нужно писать отдельный конфиг на каждое `D`. Достаточно:

```json
"task": {"distance_m": 73e-6, "duration_s": 73e-6, "hold_s": 2e-6},
"ga": {"islands": [{"strategy":"S",...},{"strategy":"K","segments":"auto","isolated_until":"100%"}]}
```

или вообще без `islands` — `K` добавится сам (`auto_add_krat` по умолчанию `true`). При `D=73` → `K=4` (73/20≈4), каждый `~18.2 мкм/18.2 мкс` с холдами, непрерывно. При `D=22` → `K=1` → `K` вырождается в обычный.

### Что выбрать в итоге

`hall_of_fame` уже содержит и прямые и сшитые. Просто берите `hall[0]` — это лучший из всех, независимо от острова. Если `hall[0].island == "K"` — значит для вашего `D` сшитый путь оказался лучше (часто для `D≥60`).


## 3. Периодические кратные без остановок (P) — убираем точки остановки, ищем оптимальный шаг

### Задача

`5×20` с холдами всё ещё останавливает ион на `1/K, 2/K...` на `2 мкс` каждый — это даёт паузы и нагрев. Хотим **без остановок**: `100 мкм/100 мкс` как один `s(t)` (`smooth`/`sta` по всему `T`), но `ΔV(s)` повторяется `K` раз.

При этом для `100 мкм` разные разбиения `10×10`, `5×20`, `2×50` дают одинаковую суммарную `D`, но `n` разный — оптимально `5×20`. Нужно **авто-перебор** `K` и выбор минимума `n`.

### Как устроены P-острова

- **Стратегии `P`, `P5`, `P10`, `P2`...** — аналогично `K`, но **periodic**: `P` = `auto` (`round(D/20)`), `P5`=5 повторов, `P10`=10, `P2`=2. Также `pop 10-12`, `isolated 100%`, `baseline sta`.
- **Внутри:** `Runner.commands_krat_periodic(theta, repeats)` :
  - `s(t)` — один `smooth/sta` по всему `T` (без холдов на `1/K`), `route = q(s)` непрерывно `0→1`.
  - `s_k = (K·route) % 1` — фаза внутри периода, `env_k = 16 s_k² -32 s_k³ +16 s_k⁴` — огибающая **per period** (ноль на границах периода и на финальном холде).
  - `ΔV = (basis_k(s_k) @ theta_volt) @ correction_modes`, где `basis_k = [env_k, env_k(2s_k-1), env_k(6s_k²-6s_k+1), env_k sin2πs_k, ...]` — тот же набор, но **K-периодический**. Поэтому одно `theta` задаёт повторяющийся профиль напряжения `K` раз.
  - `v = voltage_spline(route) + ΔV` — один `Hardware.deliver` по всему `t`, затем `ROM + propagate` — `n_total` для всего пути, сравним с `S` и `K`.
- **Фитнес:** тот же `scalar_fitness`. Для `theta=0` все `P` дают одинаковый `n` (ибо `ΔV=0`), но при оптимизации `P5` обычно находит `n` меньше `P10` и `P2` на `100 мкм` — в `hall` побеждает `P5`.
- **Авто-добавление для любого D:** `GAEngine` сам добавляет `P (auto)` + до двух альтернатив (`P2`, `P10` или `P5`) в зависимости от `D`, если `auto_add_periodic != false` и явных `P` нет. Примеры авто:
  - `D=100 → P auto(5) + P2(2×50) + P10(10×10)` — в `hall` три `P` соревнуются, лучший `P5` обычно выигрывает.
  - `D=60 → P auto(3) + P5 + P2`
  - `D=30 → P auto(2) + P5`
  - `D=150 → P auto(8) + P5 + P2`
  Все изолированы 100%, без миграции, но в `hall` вместе с `S/A/K`.

### Почему отдельные изолированные и без холдов

- **Без холдов:** ион не останавливается на `1/K` — нет промежуточных `hold 2 мкс`, траектория `r(t)` непрерывна, `distortion` меньше (нет резких `hold` фронтов через фильтр).
- **Отдельные острова:** `K` (с холдами) и `P` (без) — разные физики, не должны смешиваться миграцией. `P` и `K` оба `100% isolated`, но их лучший `theta` сравнивается в `hall` честно по `n`. Для `100 мкм` обычно `S n~32`, `K5 n~3.2`, `P5 n~4.2` (`theta=0`); после оптимизации `P5` может обогнать `K5` из-за отсутствия холдов.
- **Дашборд:** `P` — оливковый `#7af0a0`, `P10` — синий `#2ec4ff`; в **Islands** таблице `segments` показывает `repeats`, в **Trap** — `P` без ступенек, `K` со ступеньками; **Migration** — `P` также тёмный изолированный.

### Как запустить

```json
"task": {"distance_m":100e-6, "duration_s":100e-6, "hold_s":2e-6},
"ga": {"islands":[
  {"strategy":"S","pop":12,"baseline":"smooth"},
  {"strategy":"K","pop":12,"baseline":"sta","segments":"auto","isolated_until":"100%"},
  {"strategy":"P","pop":12,"baseline":"sta","segments":"auto","isolated_until":"100%"},
  {"strategy":"P10","pop":10,"baseline":"sta","segments":10,"isolated_until":"100%"},
  {"strategy":"P2","pop":10,"baseline":"sta","segments":2,"isolated_until":"100%"}
]}
```

или просто без `P` — они добавятся авто (`auto_add_periodic:true` по умолчанию) при `D≥25 мкм`.

На выходе `hall[0].island` подскажет победителя: если `P5` — оптимально `5×20` без остановок.
