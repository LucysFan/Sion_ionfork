# Island GA — полная архитектура для shuttling + GDS + experiment

> Цель: генерить **много разных маршрутов иона** (не один `Powell` локальный), из них собрать Парето-фронт для GDS, добить лучший на эксперименте `closed-loop 8 dim`. Дашборд — в реальном времени, без замедления GA, плюс `CUDA` если есть.

## 1. Чем и зачем управлять — геном

**Базовый геном 8 float — это и есть низкоразмерное управление, которое потом поедет на установку:**

* `g0,g1` — `time-warp` на `env=16s²(1-s)²` (полином `P[0,0,16,-32,16]`). Меняет закон времени `s(t)` не ломая `v=a=0` на границах. Физический смысл: задержаться в середине (где `Φ` пологий) или ускориться.
* `g2..g7` — `3 огибающие × 2 SVD-моды геометрии` `ΔV = (e0,e1,e2)·Θ·R_svd`. `e0=env`, `e1=env·(2s-1)`, `e2=env·(6s²-6s+1)` — все нуль на краях, `R_svd` — топ-2 сингулярных вектора `route_V-mean` (null-space лапласиана). То есть ген не правит 200 вольтовых отсчётов, а правит 6 чисел в подпространстве которое реально двигает минимум.

**Расширенный геном 10:** 
- `V (voltage)`: `g0,g1` warp + `g2..g9` 4 базиса×2 ΔV (`env, env·(2s-1), 6s²-6s+1, env·sin2πs`) — крутит напряжение, гибкая форма не в середине.
- `W (frequency)`: `g0,g1` warp + `g2..g7` 3 базиса×2 ΔV + `g8,g9` `a·env+b·env·(2s-1)` → `ω(s)=ω0·(1+a·env+b·env·(2s-1))` `±15%` via `FrequencyProfile` variable (prepare с кэшем). Крутит частоту, видно по `fmin` 0.500→0.43..0.55 МГц. Ранее `V` был один гибридный остров, теперь разделены как просили: один напряжение, один частоту.

Границы жёсткие:
```
g0,g1 ∈ [-0.10,0.10]
g2..g7 ∈ [-0.4,0.4]
g8,g9 ∈ [-0.15,0.15] (если остров variable)
```
Это и есть `search_bounds` — не `1000` семплов.

**Что можно дотюнить:**

* **В симуляции (дешево, точно):** весь геном `10`, `route_nodes`, `regularisation`, `frequency_mode`. Можно даже менять `SVD-моды` (пересчитать `R` на новом `sroute`).
* **На эксперименте (дорого, шумно):** тот же `8-10` генов через `ClosedLoopRefiner` + `SafetyLayer`. Плюс калибровка `gain/offset/delay/filter` — отдельный слой `calibration.py`, не чёрный ящик. То есть GA ищет в симуляторе, эксперимент только `fine-tune` 8 чисел.

## 2. Конечные цели — не один лосс

Иерархия §8 спеки:
1. **Safety** — `Rejected` → `fitness=1e6` (no_minimum, infeasible, saturation, weak_confinement, slew)
2. **Confinement** — `fmin < min_frequency_hz` → `+log1p`
3. **Hardware** — `max_deviation_V`, `rms`, `clipping`, `slew`
4. **Возбуждение** — `log1p(n/n0)` где `n0=max_n_total` (фононы) + `log1p((pos/tol)²)` + `log1p((well/tol)²)`
5. **Робаст** — `0.35mean+0.65max` по `3 train` сценариям (`gain/offset/delay/filter/stray/freq_scale`) + `CVaR20` для хвоста
6. **Эстетика** — `1e-4·||θ||²`

Итоговый скаляр `fitness(θ) = scalar(primary)`, но в дашборд пишем все компоненты отдельно: `n_total`, `n_modes`, `pos_err`, `well_err`, `fmin`, `slew`, `distortion`, `mean_n`, `worst_n`, `cvar` — чтобы видеть **вариации**, а не одну линию.

## 3. Острова — зачем 5 разных (STA — не догма)

Каждый остров — отдельная популяция `20` особей, свой `baseline` и свой уклон. Алгоритм **не ограничен STA**: `STA` — лишь один из `baseline` (`smooth` vs `sta`), а геном `θ` правит сверх него. Диверсити сохраняется нишами и явным критерием в зале славы:

* **Island-S (Smooth):** `baseline=smooth` `s³(10-15s+6s²)`, мутация `σ0=0.04` малая, `k=3`. Ищет адиабатику без `STA`-члена `s''/(Tω)²`. В эксперименте «радует» больше — не требует точной второй производной, которую съедает `DAC lowpass`.
* **Island-A (STA):** `baseline=sta` `35s⁴-84s⁵+... + s''/(Tω)²`, `σ=0.06`, `k=5` — любит короткие `T`, но чувствителен к ангармонизму и фильтру.
* **Island-V (Voltage):** геном `10`, `σ 0.08`, `cx 0.9` — `4 базиса×2 ΔV (env·sin2πs)` — крутит **напряжение** (гибкая форма не в середине).
* **Island-W (Frequency):** геном `10`, `σ 0.08`, `cx 0.9` — `3 базиса×2 ΔV + 2 freq a·env+b·env·(2s-1)` → `ω(s)=ω0·(1+a·env+b·env·(2s-1))`, `±15%` via `FrequencyProfile` variable (prepare с кэшем). Крутит **частоту**, спасает `100мкм ±12В` и `h90` с `≤1.2МГц`.
* **Island-R (Robust):** фитнес на `3 train` сценариях, `worst` вместо `mean`, популяция `25` — отбирает устойчивых, а не быстрых.
* **Island-H (Hardware):** `fitness +=0.5·log1p(rms/0.1)` — штрафует за искажение фильтром, генерит пологие `V(t)`.
* **Island-F (Free, опционально):** `baseline=smooth` + `10` генов, `σ 0.07` — «свободный» полином без привязки к `STA`/`smooth` формуле, `ΔV` полностью свободен в `R_svd` подпространстве (чистый численный оптимум). Включается как `strategy F` в `ga.islands`.

Размер `6×20=120` особей (S,A,V,W,R,H) — каждую генерацию `120` `Runner.evaluate(cheap ROM)` ~ `0.4с×120=48с` но с `multiprocessing 4` → ~12с. W кэширует `prepare()` по `freq_coeffs` (64 ключа) → оверхед <2%. Дешёвая `ROM` без `trap.local exact`, точные `321 node` только для `hall of fame`.

**Почему STA «не радует» в эксперименте и как GA это обходит:** `STA` выводится для идеального гармонического `ω=const`, ангармонизм `h90`, `DAC 1МГц+500кГц` и `max_jump 1В` ломают член `s''/(Tω)²` → перерегулирование. `Smooth` + `θ`-коррекция (`e0,e1,e2` на `R_svd`) генерит семейство **не-STA** траекторий, `V`/`F` — вообще свободные. GA отбирает по реальному `n_total`, а не по красоте формулы.

## 4. Миграция, холл и критерий отличия траекторий

Топология **кольцо** `S→A→V→W→R→H→S`, каждые `5` поколений мигрирует `2` особи: `лучшая` + `самая дальняя по θ`-расстоянию (поддерживает диверсити). Замещение — убиваем `2 худших` острова-приёмника. Раз в `15` поколений — глобальный `shuffle` 1 случайной особи во все острова (избегаем дрейфа).

**Холл славы — с фильтром разнообразия (критерий отличия):** не просто `top-N` по `fitness`, а жадный отбор по фенотипу `distance(θ)`.

* нормализованное евклидово `θ∈[0,1]⁸` : `d = ||θ̂-θ̂'||₂`, `θ̂_i=(θ_i-lo_i)/(hi-lo_i)`; для `V/F` 10-мер сравнивается префикс 8;
* `min_dist = hall_diversity_min_distance` (дефолт `0.12` ≈ `15%` диапазона) — если `d < min_dist` к уже взятым, пропускаем близкого конкурента STA-кластера;
* если разнообразных не хватило — добиваем лучшими по `fitness`.

`d(θ)` — прокси траектории: `ΔV = (basis·Θ)·R_svd → Δr ≈ H⁻¹·G·ΔV`, поэтому `θ`-дальность ≈ `L2` между `well(t)` и `V(t)`. В `state.json` пишем `hall_diversity = mean pairwise d` и `islands[].diversity`, в дашборде — гистограмма и `Pareto n vs worst`. При желании можно включить точную фенотипическую метрику `‖r₁(t)-r₂(t)‖₂` вместо `θ`.

Штрафы реализованы как **жёсткие + мягкие:**
* жёсткие `Rejected` → `fitness 1e6` и `status=code` логируется (не трейсбек)
* мягкие: `if fmin<0.4МГц: fitness+=2·log1p((0.4-fmin)/0.1)`, `if slew>0.9·max_jump: +1`, `if |θ|>bounds: +inf` (клип)

Так острова не схлопываются в одну нишу — `S` остаётся гладким, `V` — напряжением, `W` — частотой, `F` — свободным, а холл держит **разные ветви**, а не 10 клонов STA.

## 5. CUDA — если есть, не мешает если нет

`shuttle_sim/ga/cuda.py`:
```python
try: import cupy as cp; HAS_CUPY=True
except: cp=np; HAS_CUPY=False
try: import numba; HAS_NUMBA=True
except: HAS_NUMBA=False
```
* `dynamics.propagate` матричные `S·C·Sᵀ` 6×6 — если `HAS_CUPY` и `N>500` (длинный `repeated`), то `C` как `cp.ndarray` и `cupy.matmul` (~1.8× быстрее на `V100`).
* `Hardware.deliver` RC-каскад `expm` — остаётся `scipy.linalg.expm` (CPU), CUDA не трогает `trap.local` (`least_squares` — CPU).
* Параллельность GA — `multiprocessing.Pool(4)` по островам, каждый воркер может внутри использовать `cupy` если `has_cupy`. Если `HAS_CUPY==False` — прозрачный `numpy` fallback, обучение не замедляется.

Проверка `cuda.is_available()` пишет в `manifest.json`.

## 6. Дашборд реального времени — не тормозит GA

**Архитектура без замедления:**
* GA пишет **атомарно** `output/ga_run/state.json.tmp → state.json` после каждой генерации (~50мс) + `history/ gen_*.json`
* Отдельный процесс `dashboard/server.py` (Flask `0.0.0.0:8000` → preview `https://8000-xxx.e2b.app`) **только читает** файл, `GA` его не ждёт. Поллинг `500мс` или `SSE`.

**Что видно (не просто loss):**
* `loss` — `best/mean/worst` на остров и глобально, `worst` робаста отдельно
* `diversity` — `σ(g0..g7)` и pairwise `θ`-расстояние
* `n_total` гистограмма на популяцию (лог шкала), `pos/well err` scatter
* `hall of fame` — 10 лучших `θ`, их `V(t)` 15 каналов, `r(t)` траектория, `f(t)` профили
* `hardware` — `max_deviation_V` vs поколение, `slew`
* `migration` — граф кольца, вспышки при `migration`
* `Pareto` — `n vs robust worst` фронт

Фронт — `Chart.js` + `Plotly` heatmaps, `index.html` статика, `fetch /api/state` каждые `500мс`. GA продолжает мутировать.

Запуск:
```bash
python -m shuttle_sim.ga --config configs/shuttle_ga_island.json --out output/ga_100um --dashboard --port 8000
# → http://localhost:8000  (в E2B → Live Preview)
```
Если `--dashboard` не указан — GA всё равно пишет `state.json`, дашборд можно поднять потом.

## 7. Изолированные острова — "карантин"

По запросу: не отказываемся от `STA/smooth`, но делаем **совсем пустые острова**, которые `N` эпох живут изолированно и лишь потом вливаются в общую систему.

* `isolated_until: 12` в `ga.islands[]` — остров `Q1` `12` поколений не участвует в кольце (ни не отдаёт, ни не принимает), эволюционирует сам.
* `Q2 isolated_until: 18`, `F isolated_until: 15` — несколько таких карантинов с разными `baseline` (`smooth/sta/free 12dim`) и `σ`.

Механика `shuttle_sim/ga/migration.py:RingMigration`:
- `should_migrate` — пропускает изолированные,
- в `migrate(generation)` — если `generation == isolated_until`, делаем `burst`: лучший+самый дальний из проснувшегося острова рассылаются всем активным,
- `global_shuffle` тоже только среди активных.

В `island.snapshot()` — поля `isolated_until`, `is_isolated` для дашборда (серая иконка карантина). Пример конфига `configs/shuttle_ga_isolated.json` — 5 основных + 3 карантина `Q1 12`, `Q2 18`, `F 15`.

Так получаем **чистый поиск без навязывания формы**: изолированные острова могут найти совсем другую ветвь (например двумя провалами `ω(s)` в `0.2` и `0.7`, а не в середине), и лишь потом она конкурирует в общем холле (холл тоже с `min_dist 0.12`).

## 8. Trap-отображение и анимация шаттлинга — отдельная вкладка «Trap · Animation» (3% лучших на остров)

**Требование:** дашборд рисует саму ловушку и анимирует шаттлинг внутри неё для **каждого острова отдельно по 3% лучших кандидатов** (`ceil(pop·0.03) ≥1`, для `pop 20 →1`, для `pop 100 →3`; капается до `3` чтобы не раздуть `state.json`), **не замедляя обучение**.

**Как это не тормозит GA (design non-blocking):**

* **Файл-опрос, а не блокировка.** GA пишет `state.json.tmp → state.json` атомарной заменой (`Path.replace`) после каждой генерации (~30 мс на 300 kB). Дашборд — отдельный `python -m shuttle_sim.dashboard.server` процесс на `0.0.0.0:8000`, только `GET /api/state` каждые `500–900 мс`, `GA` его не ждёт, никакого `GIL`/`Queue` между процессами.
* **Дешёвая ROM + децимация.** Траектория для анимации — `Runner.evaluate(theta, baseline, exact_nodes=None, return_trajectory=True, trajectory_decimate=80)` (линейно-откликовая ROM без `trap.local` циклов) ≈ `5–8 мс` на кандидата против `~2 с` для `exact_nodes=200`. Для `8 островов ×1 →8×6 мс ≈48 мс` раз в `trap_traj_interval=2` поколений, т.е. ≈ `24 мс/поколение` оверхед < `2%` от `~1 с/поколение·100 особей`.
* **Кэш по хешу `θ`.** `_traj_cache[(strategy, baseline, round(θ,5), decimate)] → trajectory` — повторная оценка того же генома не идёт в `Runner`; при стагнации острова кэш даёт `0 мс`. Лимит кэша `300` записей (LRU 50).
* **Интервальная свежесть.** `trap_traj_interval` (дефолт `2`) — пересчёт только каждую 2-ю генерацию или на последней; в промежуточных — отдаётся закэшированный `island_trajectories` (поколение всё равнодвижется). `hall best` траектория отдельно `exact_nodes=200, decimate 250` раз в `2` поколения.
* **Фронтенд 60fps, бэкенд 0.5fps.** Анимация `requestAnimationFrame` интерполирует уже децимированные `times_s / mean_positions_m / well_centers_m` (≈ `80` точек) линейно по времени; поллинг лишь подменяет массив когда GA обновил `state.json`. Видеопетля `2 с/шаттл` при `1×` скорости.

**Что пишется в `state.json`:**

```json
{
  "trap": {"kind":"sion_five_wire","electrodes":[{"name":"rf[0]","type":"rf","paths":[[[x,y],...]],"rf":...}],"bbox":{...},"start_m":[0,0,90e-6],"target_m":[30e-6,0,90e-6],"distance_m":30e-6,"duration_s":15e-06,"height_m":90e-6,"geometry_raw":{...}},
  "island_trajectories": [{"island_id":0,"strategy":"S","pop":20,"k":1,"candidates":[{"rank":0,"theta":[...],"fitness":1.23,"status":"excessive_excitation","trajectory":{"times_s":[...],"mean_positions_m":[[x,y,z],...],"well_centers_m":[[x,y,z],...],"well_times_s":[...],"_n_total":0.42}}]}]
}
```

`_get_island_top_trajectories()` сортирует популяцию по `fitness`, берет `k = ceil(pop*0.03)` (≥1, ≤3), вызывает `evaluate` с `return_trajectory`.

**Вкладка Trap во фронте (`dashboard/static/index.html`):**

* **Два канваса:** `cTrapTop` (top view `x vs y`, `±350 µm` corridor, `y -350..350`, RF gold `#ffbe55`, DC blue `rgba(90,200,255,0.28)`, центральная `DC` серая, shuttle-коридор `rgba(122,240,160,0.07)`) и `cTrapSide` (`x vs z` высота `90 µm`, `75..105 µm`, поверхность кристалла `z=0`). Мировая `µm → canvas` через линейный `xToCanvas/yToCanvas`, электроды клиппятся вьюпортом.
* **Трейлы и точки:** для каждого кандидата `well` (тонкая `1.6px`, `α 0.55`) и `ion <r>` (толстая `2.2px`) до `curT = gmin+prog·(gmax-gmin)`, точка `curMean` с радиальным градиентом + `well` пунктирным кольцом, цвет острова `COLORS`. Прозрачность падает с `rank`.
* **Управление:** `▶ play / ■ stop` (`trapLoop` via `requestAnimationFrame`, `wallPerShuttle 2s`), скорость `0.25–4×`, слайдер `progress 0..1` (`sliderTrapTime`), чекбоксы `well/ion/side`, `view {shuttle,full,zoom}`, фильтр островов `trapIslandFilters` (чекбоксы, клик по кандидату изолирует остров). Легенда `t=…µs`.
* **Адаптивный вьюпорт:** `shuttle` вычисляет `xMin/xMax` как `min/max well.x ±200 µm` (дефолт `cx ±350 µm`), `full` — полный `bbox −10..10 mm`, `zoom` — `cx ±90 µm`. Side `zMin/zMax` `75..105` vs `0..150`.
* **Кандидаты:** сетка `trapCandidateList` — карточки `S #0 fitness 1.23 n=…` с мини-`θ`, клик изолирует остров. Бейджи `Trap 17 electrodes`, `cands 8`.
* **Polling:** `setInterval(poll,900)` + `drawTrap` после каждого `fetch`; `drawTrap` интерполирует `interpolatePos(t, times, positions)` бинарным поиском.

Так получаем: **острова держат диверсити, изоляции дают независимые ветви, миграции не дают застрять, штрафы делают физику, CUDA ускоряет если есть, дашборд показывает всё живое без `GIL` блокировки — плюс Trap-вкладка анимирует 3% лучших каждого острова внутри реальной геометрии не тормозя GA.**
